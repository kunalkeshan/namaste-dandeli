## Why there is no `aggregateRating`

**Do not add it.** Google's review-snippet policy is explicit: if the entity being
reviewed controls the reviews about itself, its pages using `LocalBusiness` or
`Organization` structured data are **ineligible** for the star feature. It also says
plainly: _"Don't aggregate reviews or ratings from other websites."_

Copying his Google rating into our own markup is precisely that. Consequence: not a
manual action by itself, but **the markup renders nothing**. Pure downside.

**What we do instead:** show the 4.9 and the reviews as visible HTML, attributed to
Google, linked to the listing. Fully allowed, and it is what converts. His stars
already appear where taxi searchers see them — the local pack, which Google controls.

`pnpm verify:content` fails the build if `aggregateRating` appears.

## Technical

|                 |                                                                                 |
| --------------- | ------------------------------------------------------------------------------- |
| `lang`          | `en-IN`. **No hreflang** — single locale; adding it is a common pointless error |
| Canonical       | from `site` in `astro.config.mjs`, overridable via `SITE_URL` for previews      |
| Sitemap         | `@astrojs/sitemap`, excludes `/og` and `/styleguide`                            |
| robots.txt      | allows everything except those two                                              |
| OG card         | `public/og.jpg`, 1200×630, generated by `pnpm og`                               |
| Core Web Vitals | LCP < 2.5s, **INP < 200ms** (INP replaced FID in 2024), CLS < 0.1               |
| Analytics       | GA4, inline `gtag.js` from `src/content/analytics.ts`. No GTM container         |

The OG card carries the review count, so **regenerate it when that number moves**.

**Analytics is GA4 only, and unrelated to the `aggregateRating` rule above.** It
uses the `gtag/js` install with `gtag('config', …)` for a `G-` measurement ID —
not a Tag Manager container. Google's generic Tag Platform install page shows a
`gtm.js` snippet and calls `gtag('config')` deprecated, but that describes a
`GTM-` container; pairing a `G-` ID with `/gtm.js` is explicitly unsupported.
`async`, so it never competes with the LCP hero preload. See
`docs/launch-runbook.md` §4 for the two custom dimensions that must be registered
or the event params never appear in reports.

## Keywords worth chasing

Route and station long-tail — low volume, near-zero competition, high intent:
`hubli to dandeli cab` · `dandeli airport pickup` · `alnavar to dandeli taxi` ·
`londa to dandeli cab`

**Skip anything with "package"** — resort/tour queries are aggregator-dominated.

His reviews _are_ the keyword map: Goa, Gokarna, Hubli, Belgaum, Mysore–Ooty,
Kumta–Udupi–Murudeshwar–Mangalore, Londa, Alnavar are all real completed trips.

## When to go multi-page

One page holds one `<title>` and one `<h1>`. Expand when Search Console shows a route
query at position 8–20 — demand confirmed, page strength the gap. Astro makes the
plumbing cheap, **but each page needs genuinely unique content or they are doorway
pages**, which is a real penalty risk. The cheapness is the trap.
